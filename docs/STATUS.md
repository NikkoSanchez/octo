## Known limits and next work

1. **Agent hardening:** live harness smoke tests, richer tool output, Claude model/reasoning controls, additional provider settings, token accounting, reconnection, more approval/request types and cancellation races. Resource limits and process-group shutdown are implemented; deliberately detached descendants remain outside that ownership boundary.
2. **Workspace lifecycle:** archive/restore and undo for removed threads/projects, explicit worktree creation/selection, branch operations and multi-window ownership. Current new threads use the project's current checkout; Octo does not isolate them automatically.
3. **Review polish:** side-by-side rendering, character-level changes, proper syntax grammars, search, line-gutter selection, reliable copied-source formatting, and performance benchmarks. Ordinary native Copy includes visible gutter text; Ask Agent strips gutters. File listings exclude ignored files and do not traverse submodule contents. File previews reject symlink components, including links inside the checkout. No stage/commit UI.
4. **Refresh:** manual, app activation and turn-completion refresh are present; filesystem watching is not. A captured attachment intentionally remains a snapshot after edits.
5. **Persistence:** whole-archive JSON with debounced atomic saves; sent screenshots are embedded as base64 PNG data and increase archive size. Separate asset storage is future work. Drafts, approvals, running processes and terminal scrollback do not survive quit. No migrations beyond version rejection, database paging, transcript pruning or multi-process writer protection.
6. **Terminal and keyboard:** test IME, VoiceOver, international layouts, custom Ghostty bindings, long-running sessions and large scrollback. Reserved app shortcuts take precedence over conflicting Ghostty bindings. Shortcut remapping is not yet exposed. Transcript find navigates matching messages, not individual occurrences; search scans the loaded archive without an index. Configuration reuse currently checks `~/.config/ghostty/config`; other Ghostty config locations are not discovered. Missing named Ghostty theme resources can cause the wrapper to fall back to defaults (observed for TokyoNight Moon in the isolated bundle); Catppuccin overrides do not depend on external theme files. No specialized herdr integration; run herdr in an ordinary shell tab.
7. **Packaging:** development bundle only, pinned community Ghostty binary, no distribution signing identity/notarization/updater/distribution license. App sandbox is off because local tools need filesystem/process access; Codex tool sandbox policy is a separate CLI boundary.
8. **Security review:** the pre-publication audit found no credential matches in the candidate source upload. Transcript permissions, editor socket isolation, process resource bounds, file-preview containment and CI permissions have been hardened. See [the audit and its limits](SECURITY_AUDIT.md). Common credential files, workspace exports, and logs are now ignored; personal checkout details were removed from this document.

## Model-control references

The composer uses model-specific reasoning choices and retains unavailable selected labels, informed by [T3 Code's ProviderModelPicker](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/chat/ProviderModelPicker.tsx). Protocol fields are verified against installed Codex CLI **0.151.0**, app-server **v2** generated schemas (`ModelListResponse`, `ModelListParams`, `ThreadStartParams`, `ThreadResumeParams`, and `TurnStartParams`), with [upstream app-server documentation](https://developers.openai.com/codex/app-server). Model lists are discovered at runtime rather than hard-coded. Catalog discovery has been exercised against the installed CLI; generation remains fixture-tested only.

Executable discovery fix: this Mac's Homebrew CLI 0.151.0 returns only GPT-5.6/GPT-5.5 in the visible catalog; the ChatGPT-bundled CLI 0.158.0-alpha.2 also returns GPT-6 Astra, Sol, and Luna. Automatic selection now uses the latter. Desktop-app paths are integration conventions, not a stable embedding contract; custom selection covers other locations. The version probe uses the bounded finite-process runner with its 30-second deadline.

Screenshot input mapping was checked against Codex CLI 0.158.0-alpha.2 app-server v2 `TurnStartParams.UserInput` (`image`/`url`) and `Model.inputModalities`; see [app-server input documentation](https://developers.openai.com/codex/app-server). Protocol delivery is tested with a local fixture, without paid generation.

## Permission, reasoning, and usage protocol references

Checked against installed Codex CLI **0.158.0-alpha.2**, app-server **v2** generated `ThreadStartParams`, `ThreadResumeParams`, `TurnStartParams`, `ApprovalsReviewer`, `SandboxPolicy`, `GetAccountRateLimitsResponse`, and reasoning-summary notification schemas. See [official app-server documentation](https://developers.openai.com/codex/app-server). The UI does not invent provider reasoning or quotas. Auto-review is conservatively hidden for older/unrecognized CLI versions; CLI policy errors remain authoritative. Only supported summary text is surfaced, and older message phase metadata cannot be reconstructed. Usage is refreshed on opening/manual request and by notifications while a harness is connected; there is no background polling or spend-control/reset-credit management.
