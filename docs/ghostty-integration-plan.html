The important API distinction

The interface that exposes the full macOS terminal is include/ghostty.h, an internal embedding interface tailored to Ghostty’s own app. The public libghostty-vt library supplies terminal emulation; using it alone would leave Octo to provide rendering, PTY/process integration and much more native behavior. For current feature parity, this plan intentionally chooses the internal macOS interface and accepts the ongoing compatibility work.U3U4

This is an ownership and provenance change. No malicious behavior was established in this review. Pinning the existing archive checks its bytes; it does not independently prove how those bytes were built.

Build ownership

Record more than a SHA

Source and header hashes, Zig download digest, Xcode/SDK, architecture/deployment target, flags, patch/resource inventory and artifact digest belong in the build record.

A checksum confirms artifact integrity. Byte-for-byte reproducibility needs separate repeat-build evidence; do not claim it from a manifest alone.

Verified source-build flags and bootstrap order

These flags build successfully through Scripts/build-ghostty.sh, which additionally disables Sentry and pins Zig 0.15.2. Verified with Xcode 26.3, macOS SDK 26.2 and Apple’s Metal compiler on arm64. Other runtime platforms remain unverified.

# Run in the pinned official Ghostty checkout.
zig build -Doptimize=ReleaseFast \
  -Dapp-runtime=none \
  -Dversion-string=1.3.1 \
  -Demit-xcframework=true \
  -Demit-macos-app=false \
  -Demit-docs=false \
  -Dxcframework-target=native

# Host architecture only. 1.3.1 universal also emits iOS slices;
# a macOS-only universal recipe and Intel validation remain future work.

The official builder writes macos/GhosttyKit.xcframework, using its own ghostty.h and module map. Its full XCFramework path also installs resources. Stage the verified framework and selected matching assets into Octo’s build/package layout.U6

Order matters: fetch/verify tools and source → build framework → validate/stage assets → resolve the local binary target → swift test / Xcode app build. A local binary target cannot point at a nonexistent framework during package resolution.

Do not copy package-specific flags such as its custom shader/inspector trim options into an upstream command without checking support. Pin the complete toolchain; the public build page’s Zig table currently differs from this commit’s manifest.

Decisions we must make deliberately

Known costs & unknowns
Internal API compatibility

Known constraint Full embedding is not a supported general-purpose SDK contract. Pin header and library together; isolate the interface behind OctoGhostty. An upstream upgrade can require code changes. Revisit a public full embedding library if one becomes suitable.

Community patch behavior

Needs experiment The pinned package contains macOS rendering, scrolling and resize-related patches as well as mobile/host-managed-I/O work. Octo uses normal .exec; it does not need the package’s host-managed backend. Start unpatched, compare behavior, and carry only independently justified minimal Octo patches with tests and removal criteria.

Render scheduling

Recommended Use official wakeup → main-thread app ticks and Ghostty’s renderer scheduling. Keep ticks draining for hidden sessions; visibility should suppress focus/rendering, not session progress. The native source-build smoke works with upstream scheduling; no additional display-link dependency is used.U7U9

Clipboard policy

Explicit behavior choice Before migration, Octo installed no clipboard-confirmation handler. The pinned wrapper auto-allows confirmation requests for user paste and denies program-originated confirmation requests; ordinary allowed writes are a separate path. Preserve ordinary copy/paste and config policy, add an explicit native decision for protected operations, and document that intentional safety improvement. Never auto-approve terminal clipboard reads.

Resource and config parity

Needs inventory Terminfo, shell integration, fonts/themes and engine data can affect launch, prompt tracking and rendering. Inventory what is actually built and bundled. Review individual resource and transitive licenses; the root Ghostty MIT license alone is not a complete redistribution inventory. The new bundle includes matching upstream theme assets; individual theme compatibility still depends on the selected configuration.

Toolchain & platform reach

Unverified A universal archive does not prove runtime compatibility. Today’s local build targets the host; Intel, Release and macOS 14 runtime coverage are recorded gaps. Keep the advertised macOS 14 floor and validate it explicitly. Native arm64 is the first spike, not a silent platform reduction.

Trust and maintenance

Scope boundary This removes the community wrapper/build publisher from the chain. Ghostty, its dependencies, Zig, Apple SDKs and our build environment remain trusted inputs. Audit the resolved dependency graph, preserve notices, keep provenance, and review upgrades. No release publishing, notarization or app-sandbox migration is included here; provider approval boundaries stay unchanged.

Adoption & rollback

Switch at a safe boundary

Validate the source-built backend in an isolated development app first. Cut over on app launch after the gate passes; do not attempt to move live PTYs between libraries.

A pre-migration source commit is a documented rollback option, which would explicitly restore the former dependency. Never add a silent runtime fallback to the community package.

Update README, architecture, status and dependency-review evidence with the final pin, new setup requirements, verification and remaining limits. No release/publish workflow is assumed.
