Proposed architecture

Native where you touch it. Proven engines underneath.

This is an implementation direction, not an integration already built or tested.

SwiftUI appOwns the workspace
Projects & threadsProject sidebar with nested chat threads, session history, worktrees, activity and saved layouts.
Native chat & controlsMessages, tool events, provider-specific approvals and session actions.
Split workspaceResizable panes, focus shortcuts, file selection and per-project restoration.
Typed events and commands ↕ Shared project / worktree identity
Three integration boundariesPrototype these first
Harness adaptersConnect to each provider’s supported protocol. Start, resume, interrupt and stream events where supported. Show capabilities explicitly.
Ghostty terminal surfaceAppKit view hosted by SwiftUI, using libghostty. One terminal workspace per project, with tabs owned by the app. Run any terminal program. “Open in LazyVim” resolves the selected file and worktree, then focuses the matching editor tab.
Pierre review surfaceBundle @pierre/diffs in a WKWebView; optionally @pierre/trees beside it. Swift owns Git and file access. Web UI emits typed selection / review intents.
Local execution ↕ Durable session identifiers
Local services & storageSeparate from rendering

Git status and diff snapshots · file watching · local CLI processes · session metadata · layout persistence. Keep terminal processes alive when switching project or thread. Surviving app exit is a separate lifecycle decision, not promised by this concept.

One owner for every session.Native chat talks to a harness adapter. Each project also has a terminal workspace with independent tabs. A tab owns its process and checkout; LazyVim is simply a program running in a tab. Opening a diff file focuses or creates a matching editor tab without interrupting another process.

01Projects give everything a home

Projects contain chat threads and one terminal workspace. Thread selection restores the conversation and its changes; Terminal focuses your project’s tabs.

02The terminal is a main workspace

Each project has a terminal workspace. Open tabs for whatever you need. LazyVim runs there with your configuration; return to the thread when you’re done.

03Review stays beside the work

Inspect a diff, jump into LazyVim, then return to the same change. Pierre renders the code; the app manages the underlying files.

What I hear you asking for

A native home for multiple harnesses.

Keep the project organization you like in Codex, the provider flexibility of T3 Code, and the hands-on terminal workflow you already have. The app should make moving between directing, editing, and reviewing feel natural.

EverydayChoose a project → run an agent → inspect its changes.
Hands-onOpen in LazyVim → focus the project terminal → edit → return to the thread and diff.
Terminal tabsKeep an editor, dev server, or shell open in separate tabs within the project terminal.
Suggested first build

Prove the three seams first.

01 · TerminalEmbed Ghostty in a project terminal workspace. Confirm tab switching, LazyVim, paste, resize and key handling with your actual config.
02 · ReviewLoad a real Git diff into Pierre in WKWebView. Round-trip file and line selection back into Swift.
03 · HarnessesMake one structured session work end to end, then add a second provider to verify the adapter boundary.

Then connect projects, worktrees and layout persistence. Remote access, automatic delegation and cross-provider handoffs can follow after the local workflow feels right.

Working assumptions & integration questions
Native UISwiftUI shell with AppKit interop for terminal hosting and WKWebView for Pierre. Pierre itself is a web surface, not a SwiftUI control.
Project organizationConfirmed: projects in the left sidebar with chat threads nested underneath, as in Codex and T3 Code. Split panes belong to the selected thread. Each project also has one terminal workspace with tabs. Only one project is shown at a time.
Provider choiceChoose a harness per session. Changing providers starts a separate session; transferring context is an explicit future feature. Models and approvals remain provider-specific.
Terminal ownershipThe app owns terminal tabs and embedded Ghostty surfaces. Each tab has its own process and checkout. Run herdr or any other terminal program yourself; there is no separate herdr UI mode.
Open in LazyVimFocus this project’s terminal and reuse an editor tab for the correct checkout, or create one if needed. Open the selected file through a validated Neovim integration; never inject a command into an arbitrary busy terminal.
File treeUse Pierre Trees inside the review web surface if its behavior earns the extra dependency. A native file tree remains an option for app-wide navigation.
UnverifiedExact Ghostty framework packaging, session reattachment, input-method support, native/web focus and large-diff performance need an integration spike. This mock runs none of those engines.
