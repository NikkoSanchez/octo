# Architecture

## Composition and dependencies

```text
OctoApp (SwiftUI, AppStore, ReviewModel)
  ├── OctoAgents ── OctoCore
  ├── OctoGit ───── OctoCore
  ├── OctoReview ── OctoCore
  └── OctoTerminal ─ OctoCore + GhosttyTerminal
```

AppStore composes services and owns the persisted project/thread graph. Views communicate through intent methods; adapters emit provider-neutral AgentEvents. Git operations live on GitService's actor. ReviewModel rejects asynchronous results from a superseded project or file selection.

## Agent sessions

Each active chat has its own harness instance. HarnessID and HarnessRegistry describe locally available providers; AgentHarness exposes send, interrupt, shutdown, and events. Local thread IDs remain stable independently of remote session IDs. Switching projects does not reroute running events: callbacks capture the owning thread ID.

CodexExecutable in OctoAgents resolves a custom absolute executable path first, otherwise a supported desktop-app bundle path, then PATH. A missing explicit override is an error rather than an implicit switch. AppStore persists the override in app preferences, passes the resolved binary to both model discovery and harness creation, closes idle Codex connections when it changes, and rejects changes during active Codex turns. A configuration identity invalidates model caches and ignores discovery responses from a superseded installation. Settings reports the path and `--version` output.

Codex runs a long-lived `codex app-server` over newline JSON. The client initializes, starts/resumes a thread in its checkout, then starts turns. By default it requests `workspace-write`, `on-request` approval policy, and the user approval reviewer. Provider-neutral `AgentPermissionMode` persists in optional `AgentSettings.permissionMode`; the adapter maps Read only to read-only/never, Ask for approval to workspace-write/on-request/user, Approve for me to workspace-write/on-request/auto_review, and Full access to danger-full-access/never. The chosen sandbox, approval policy, and reviewer are passed at start/resume and again on every turn, so changing a resumed thread cannot inherit a previous broader policy. Auto-review is gated to CLI 0.158.0 or newer and version-probed again by the harness before use. Unsupported saved choices block sending without consuming the draft; Selecting Full access requires a native confirmation explaining that it also becomes the new-thread default and settings are locked during a running turn. Command and file-change approvals are presented as individual decisions. Unsupported permission expansion and unsupported MCP schemas are declined with visible notices; unknown server requests return an explicit protocol error. Supported MCP forms and experimental tool questions use the neutral interaction bridge described below. The installed CLI's own policies remain authoritative.

Claude Code starts `claude -p` per turn with stream-json and session resume. Print mode has no Octo interactive approval bridge. Denied tools are surfaced; no permissive flags are substituted. Codex discovers its model catalog through paginated `model/list` requests on a separate read-only app-server connection, without starting a thread or turn. OctoAgents decodes model IDs and supported reasoning efforts; the composer consumes these descriptors. Optional provider-neutral AgentSettings persist per thread, with older archives defaulting to no overrides. Explicit model and effort choices are passed on every Codex turn, including resumed sessions; model changes preserve compatible efforts or choose the advertised default. Unavailable catalog choices are reported without consuming the draft. Claude still inherits CLI model/reasoning configuration and rejects unsupported overrides. See ADDING_A_HARNESS.md.

JSONLineProcess owns bounded framing and stderr capture. OctoCore ManagedSubprocess launches each CLI in its own POSIX process group with nonblocking pipes, bounded outbound queues, and backpressure to MainActor protocol handling. Stop signals the group, escalates from TERM to KILL after 300 ms, drains briefly and reaps the child. Finite commands additionally have a 30-second deadline and an 8 MB combined output limit. Deliberately detached descendants are outside this lifecycle boundary; it is not a sandbox. Complete, fragmented and EOF protocol frames share the 8 MB inbound limit. Unrelated inherited file descriptors are closed at spawn. RPCConnection matches request IDs and propagates disconnects/timeouts. This transport is internal to OctoAgents; protocol fixtures test it without a paid model request.

## Context and token usage

The composer renders a native context ring and detail popover, separate from account quota controls. Provider-neutral `ConversationUsage` snapshots contain the latest model response and cumulative session token breakdowns; optional fields on `WorkspaceThread` preserve the latest report and compaction outcome across relaunch without changing older archives. Snapshots replace counts, never accumulate event notifications. Cache reads/writes are input subsets and reasoning is an output subset; missing values remain unavailable. The last response total divided by the reported model window is a context estimate, not a countdown to compaction or a count of unsent draft text.

Codex maps app-server v2 `thread/tokenUsage/updated` and `contextCompaction` item lifecycle events in OctoAgents. Exact thread/turn identities reject unrelated or stale updates; final accounting for the most recently completed turn can still arrive after `turn/completed`. Compaction item identities deduplicate lifecycle events. Stop, failure, disconnect, shutdown and relaunch cannot leave an active compaction indicator behind. Only provider-confirmed completion is labeled complete. Claude's current print adapter advertises neither usage nor compaction status. No model requests, polling, tokenization, compaction triggers or threshold changes are added by the meter.

## Review and captured context

GitService reads NUL-delimited porcelain status and unified diffs for the selected scope. It never stages, resets or commits files. ReviewSnapshot includes checkout, file, HEAD revision, scope and a content-derived identity. Working diffs compare the index to disk; staged diffs compare HEAD to the index. The snapshot hash captures rendered lines, not a Git object or a promise that the file remains current.

NativeDiffView wraps one AppKit NSTextView using TextKit 2. Native selection, scrolling, clipboard and contextual actions are retained. ReviewDocument maps UTF-16 ranges to the underlying source text, excluding headers and gutters. CodeAttachment carries captured text plus old/new ranges. Attaching it populates a draft; sending is explicit. Refreshing replaces the live selection but previously attached captures remain immutable and tell the agent to verify current files.

The first viewer is unified with lightweight highlighting. It is a separate module so split diff and richer syntax parsing can be added without replacing app state or harnesses. The native SwiftUI OutlineGroup file tree is built from Git-tracked and non-ignored untracked paths; full-file previews share the AppKit text surface and use a distinct file scope. Both full-file and untracked previews walk checkout-relative directory descriptors with no-follow opens, reject symlink path components and non-regular files, and bound reads to 2 MB.

The native text view tracks source-line hover and shows a gutter + button with a subtle line highlight. TextKit resolves the line geometry; ReviewDocument resolves its UTF-16 source range with a binary search over display segments. The action captures the hovered line, or the current selection when it intersects that line's source text. Headers and empty space below the document have no action; blank source lines are attachable. Snapshot replacement and scrolling clear the hover target so an old range cannot remain actionable.

## Screenshot attachments

The composer uses a plain NSTextView whose paste handler recognizes PNG/TIFF clipboard images. OctoApp converts them to bounded PNG snapshots and holds them per thread as draft ImageAttachments; paste never sends a turn. Draft removal and thread deletion release the captures. Sent messages persist PNG bytes in the local JSON archive, with backward-compatible decoding for older image-free messages. This increases archive size; separate asset storage remains future work. Up to four images per message are accepted, each up to 5 MB PNG/32 megapixels (clipboard representation capped at 30 MB).

AgentHarness accepts provider-neutral image attachments alongside text. Codex maps them to `image` inputs with PNG data URLs; no temporary filesystem path is required. Claude rejects images explicitly before launching a process. Catalog inputModalities is respected when available (older catalogs default to image-capable, per the app-server contract). Image-only turns are supported. Ordinary text paste, native undo, multiline input and explicit ⌘Return sending remain available.

## Workspace layout

Assistant response presentation uses a small lossless `MarkdownDocument` parser in OctoCore and SwiftUI block views in OctoApp. Foundation `AttributedString(markdown:)` interprets inline content. Parsing/inline interpretation run in a cancelable background task per response; the last parsed blocks plus the literal new tail remain visible during streaming. Message text is never rewritten: persistence, search and original-response Copy use the provider's string, while fenced-code Copy uses the exact body. Tool/reasoning output remains literal. This is a bounded feature subset rather than a full Markdown engine; no webview or package is involved.

Draft text lives in a separate observable `DraftStore`, consumed only by the editor subtree. AppStore's draft accessor publishes app-wide changes only when text send eligibility changes, keeping ordinary keystrokes from invalidating the transcript and terminal workspace. NSTextView remains authoritative during editing and marked-text composition; unchanged text and theme attributes are not reassigned on SwiftUI updates. The fixed-height native scroll viewport handles long drafts without elastic overscroll.

Project and thread pin preferences and project disclosure state are stored in the workspace archive; missing preference fields in older archives default to false. Stable ordering puts pinned items first without changing their project ownership. Thread rows expose a separate trailing pin button on hover or keyboard focus, keep pinned buttons visible, and show a pulsing status while their thread is running. Pinning does not select the thread. AppStore coordinates removal with harness lifecycle and refuses to remove active work.

The sidebar uses text-first child rows: chats and Terminal, including their selection backgrounds, are inset 24 pt beneath the project. Idle chat icons are omitted; a fixed trailing slot holds the Working indicator alongside the independent pin control. A subtle divider separates Terminal from a nonempty chat list. These navigation views do not own or remount terminal surfaces.

MCP integration is CLI-owned: each harness retains its server configuration, credentials, connections, tool execution and permission policy. Octo renders `ToolActivity` updates and native `AgentInteraction` forms and sends typed responses through `AgentHarness.respond`. Capabilities are declared individually in `HarnessCapabilities`; inventory is absent and never a prerequisite. Codex validates a bounded subset of form schemas, preserves exact app-access choices and scopes, and invalidates requests on provider resolution, turn completion, interruption, disconnect and shutdown. Fresh local UUIDs bind UI to a connection and turn generation; wire IDs never serve as reusable UI identity. Tool activity is deduplicated by connection/turn/item and stored as optional message metadata. Pending forms and answers are not persisted. SwiftUI has no Codex wire-format switches.

The Computer Use adapter also recognizes the installed extension's metadata-only duration advertisement on empty app-access forms. It adds a required neutral choice field for the UI, strips that synthetic field from outgoing content, and maps explicitly advertised session/always choices to `_meta.persist`. Nonempty forms retain their original constraints. Consent is never cached or automatically replayed by Octo; provider policies and lifetime remain authoritative. See CLI_MCP.md for the exact versioned metadata shape.

The selected Codex executable inherits Octo's environment and checkout, including configuration-home selection; the CLI alone loads configuration, authentication and trusted-project overrides. Version probing gates experimental question/extended-form opt-ins to 0.158+. Runtime validation still rejects unknown shapes. Claude's print-mode behavior is unchanged and its interaction capabilities remain false. See [CLI MCP support](CLI_MCP.md) for supported fields, exact scope mapping, lifecycle, setup boundaries, protocol references and verification limits.

The composer has one agent menu with Provider, Model, and Reasoning submenus, with a permission menu to its right (icon-only in narrow panes) driven by `HarnessDescriptor.permissionOptions`. Claude currently exposes CLI defaults only. Reasoning summaries, provider commentary, and tool activity within a user-initiated turn share a collapsed work-summary disclosure; answers, errors, user messages and approval cards remain visible. Search expands matching disclosures. Expansion is session-local; raw messages remain persisted and searchable. The active turn shows a live Working duration through waiting, approval, and answer streaming. Activity pulses respect Reduce Motion. Legacy assistant messages without provider phase metadata remain visible. The chat column, including conversation and composer, has an 840 pt maximum width centered in the available space.

New Thread reuses an idle, unstarted thread in the target project before creating one. Draft text and attachments remain intact, as do the choices on a populated draft. Empty drafts and newly created threads inherit the last explicitly selected provider and its remembered model, effort, and permissions. Optional archive fields store those defaults across launches, with old archives seeded from their selected thread. Existing duplicate drafts are preserved.

The navigation sidebar has a Projects header with an add-project button; each project retains its new-thread action. A geometry-based SwiftUI shell bounds the sidebar to 240–320 pt and permits a 480 × 600 pt window. Below 800 pt, the same mounted sidebar becomes an overlay with independent open state; navigation dismisses it, while returning to a wide window restores the user's wide-sidebar preference. The overlay hides underlying accessibility and input targets and pauses terminal surface rendering without ending its process. Chat/review and file/preview columns use a SwiftUI geometry-based divider that clamps widths during every resize; nesting native split views retained oversized children. Below 737 pt of main content width, review occupies the full main area instead of compressing chat. Both panes remain mounted with their split fraction intact. The right review panel can be hidden with its header button or ⌥⌘R; ⌘1 and code attachment return to the composer in compact mode. Review starts hidden; visibility lasts for the app session. Files and Changes keep their list containers mounted and remember their selections separately. Browser switching reads only the requested snapshot, retaining the existing native preview until the replacement arrives; selection actions are disabled during that handoff.

## Keyboard and appearance

WorkspaceView builds a context-sensitive command catalog shared by the command palette, Workspace menu, and a window-scoped NSEvent monitor. The same catalog supplies noninteractive shortcut badges on available controls after Command is held for 650 ms. A cancellable hold controller suppresses hints after a key press until Command is released, invalidates stale callbacks, and rechecks window/modifier eligibility at reveal time. A local flags-change monitor passes modifier events through unchanged and clears badges on key-window loss, sheet presentation, and modal contexts. The monitor runs before Ghostty handles key equivalents, recognizes only exact modifier combinations, and yields to Settings, attached sheets, and modal windows. Send/stop/attachment actions are excluded from terminal key routing. The shared palette supports project name/path search (⇧⌘K), chat-content search and flat file search. Project results use sidebar ordering; selection resolves the current archive by ID, expands the project, and requests composer focus without remounting terminals. Native NSSearchField delegates handle arrow/Return/Escape navigation and thread-find focus. Palette rows and scroll targets use stable entry IDs so filtering cannot reuse another result’s label. Selected actions run from the sheet dismissal callback before requesting destination focus, without a fixed animation timer. The find field stays mounted; workspace transitions immediately transfer or clear native first-responder focus so subsequent keystrokes cannot reach a hidden terminal. Composer and preview requests also use explicit counters without remounting the terminal. Sidebar dialogs and terminal-close confirmation are shared by mouse and keyboard actions.

AppTheme in OctoCore stores a portable identifier and Catppuccin color values. AppStore persists the choice in UserDefaults. OctoApp applies SwiftUI appearance and native composer colors; OctoReview recolors attributed text without replacing a snapshot or discarding selection. OctoTerminal uses the pinned wrapper's setTheme API to update live Ghostty configurations in place. System removes the color overlay; user configuration remains the base where supported. No Neovim configuration files are edited. See KEYBOARD.md for the shortcut contract and references.

## Terminal ownership

TerminalWorkspace owns all tabs for the life of the app; TerminalTab owns the Ghostty state. TerminalSurfaces keeps inactive tabs mounted and disables their rendering/focus. Closing a tab is an explicit action because it ends its process.

New shells use the selected project's root. Open in LazyVim targets the thread's checkout, reusing one Neovim tab for that project/checkout via a local server socket inside a uniquely allocated, owner-only directory. The directory has a short path for Unix socket limits and is released with editor exit/tab lifetime. Remote-open uses argument arrays and a JSON-encoded Lua argument. A new editor starts `nvim --listen` with the selected file and line. No keystroke injection into an unknown foreground shell is used. Existing `~/.config/ghostty/config` and Neovim configuration are reused where supported by the wrapper.

## Persistence and future growth

WorkspaceStore writes schema-versioned JSON atomically using private 0600 temporary files. The standard storage directory is 0700, and old archives are tightened on load. Archives and standard storage are excluded from macOS backups. Storage inside a Git checkout, symlinked archive files, multiply-linked files and unsafe custom parent directories are rejected. Conversations are local to each Mac and are never part of source setup or Git synchronization. Unsupported or corrupt data blocks writes for that app launch rather than overwriting the file. Save requests are debounced. Terminal processes and drafts are session-local.

This format is intentionally small and understandable. Before large histories or multiple app writers, introduce a storage protocol, transactional database, migrations, paging and a single-writer strategy. Before external plugins, replace the closed HarnessID registry with stable identifiers and a capability schema. Worktree creation, branch switching, file watching and session recovery belong in explicit services rather than view callbacks.

## Account usage

`HarnessRegistry.usage` returns provider-neutral `AgentUsage` buckets and windows. Codex initializes a separate app-server connection and calls `account/rateLimits/read`, without starting threads or model turns. Its adapter prefers the multi-bucket response and falls back to the legacy single bucket, preserves absent percentages/durations/resets as unknown, and converts Unix reset seconds to dates. The Usage popover refreshes on opening or explicit refresh, labels the account-wide scope and last update, and displays actual window durations instead of inventing a monthly allowance. Live `account/rateLimits/updated` notifications merge the affected bucket. In-memory caches are scoped to provider/checkout and invalidated on executable changes; stale responses from a superseded installation are ignored. Claude's current print adapter does not expose account-limit reads. No credentials, usage data, or permission choices are copied into source setup.

## Transcript presentation and navigation

AppStore coalesces assistant, reasoning and activity text across active chats into one archive publication per 100 ms, with a 64 KiB flush bound. Protocol boundaries, Stop, explicit saves and shutdown flush pending text first; role and tool boundaries are preserved. Transcript follow intent is owned by `TranscriptScrollController`, observing the enclosing native NSScrollView through a noninteractive SwiftUI background probe. Native user-scroll notifications pause following when more than 32 pt from the bottom and resume near the bottom; content/frame changes never pause following. “Scroll to end” explicitly resumes. The latest turn and bottom target are eagerly measured together, with older turns in a LazyVStack; this avoids blank or partial jumps caused by estimating a large streaming tail. Native frame notifications plus SwiftUI text/height changes request coalesced jumps through ScrollViewProxy after layout. Scrolling handles late Markdown layout and viewport resize, cancels pending movement during live scrolling, and disconnects observers on teardown. Thread changes start at the latest content; find pauses following, and hidden-terminal suspension retains follow intent. Probe configuration is deferred beyond SwiftUI view updates. Native review selection callbacks are deferred and deduplicated by snapshot and range; text replacement suppresses intermediate delegate callbacks so selection cannot synchronously publish SwiftUI state during `updateNSView`.

User messages appear in right-aligned rounded bubbles; assistant responses remain unboxed. Timestamp footers use each message's recorded date, with a full-date tooltip; completed assistant responses use an optional completion timestamp. `TurnWork` is optional metadata on the initiating user message. AppStore records elapsed work using system uptime, finishes it on completion/failure/interruption, and preserves stopped/failed/interrupted labels. A saved unfinished run is shown as Interrupted without inventing an end time. Older archives have no duration and continue to decode unchanged. Work details are grouped per user turn; search expands matching details.

Markdown tables use a native SwiftUI Layout that allocates columns across the available transcript width, measures wrapped cells, and sizes each row to its tallest cell. Thin horizontal separators replace boxed cells; wide tables retain horizontal scrolling. The Usage header control is chart-only with a tooltip and accessibility label.

Assistant links intercept OpenURL: HTTP(S)/mailto retain normal system routing; local destinations go through `MarkdownFileLink`, resolved against the thread checkout. Relative, absolute, file URLs, `:line[:column]`, and `#Lline` references are supported. Out-of-checkout paths and unsupported schemes report an Octo error. Native Files navigation expands ancestors, selects the file, and scrolls/selects a referenced line without attaching or sending it. Existing bounded no-follow GitService reads still enforce file containment. Folder expansion is explicit view state so link navigation can reveal nested files.
