- **Browser user agent (2026-10-16):** WKWebView's default user agent ends at the WebKit token, so Google and other browser-sniffing sites served basic fallback pages. The browser now appends exactly what Safari appends (`Version/<installed Safari version> Safari/605.1.15`, falling back to `26.0` if Safari's bundle cannot be read) via `applicationNameForUserAgent`, keeping WebKit's own platform/engine string. No other browser is impersonated: an identity that disagrees with the engine is what trips bot checks such as Cloudflare Turnstile ([T3 Code keeps Electron's native agent for the same reason](https://github.com/pingdotgg/t3code/blob/2993dfc/apps/desktop/src/preview/BrowserSession.ts#L278)). With the new agent, google.com returns its current page (247 KB, `<textarea>` search box) instead of the 88 KB fallback. WebKit caches a redirect together with its follow-up request, user agent included, and replays it on a cache hit; a `google.com` → `www.google.com` 301 (30-day max-age) cached under the old agent therefore kept producing the fallback page. When the stored agent differs from the current one (first launch with this change, or a Safari update), Octo now clears only WebKit's disk/memory HTTP cache before the first navigation; cookies and other website data are kept. Reproduced with a copy of the app's real website data (fallback page) and confirmed fixed after the discard. **218 Swift tests** (including the agent reported by a real WKWebView) and the native build pass. A visual smoke check in the app, including a Turnstile-protected login, is pending.

## Known limits and next work

1. **Agent hardening:** real MCP/Computer Use and model smoke tests, additional form/result formats, additional Claude permission/provider settings, Claude subagent token totals, reconnection, more approval/request types and cancellation races. Resource limits and process-group shutdown are implemented; deliberately detached descendants remain outside that ownership boundary.
2. **Workspace lifecycle:** archive/restore and undo for removed threads/projects, explicit worktree creation/selection, branch operations and multi-window ownership. Current new threads use the project's current checkout; Octo does not isolate them automatically.
3. **Review polish:** character-level changes, proper syntax grammars, search, line-gutter selection, reliable copied-source formatting, and performance benchmarks. Ordinary native Copy in Changes includes visible gutter text; Ask Agent strips gutters. Files copies exact source text. File listings exclude ignored files and do not traverse submodule contents. File previews reject symlink components, including links inside the checkout. The manual editor supports UTF-8 files up to 2 MB; mutations reject symlinks, hard links, Git metadata and non-regular files. New-file paths use existing folders; no folder creation/deletion or editor-draft restoration after relaunch. Opened native editors are cached in memory without eviction; large-file performance is not benchmarked. Deletion is permanent, with confirmation. Conflict checks cannot lock out independent writers between the final check and mutation. No stage/commit UI.
4. **Usage and browser:** Claude limits are in-memory and reset on relaunch until another response reports them; API-key/Bedrock/Vertex sessions never report them. `unifiedWindows` is an upstream internal field read only when present. The dashboard reads only local logs on this Mac (other machines and web/desktop app usage are absent); session counts differ slightly from T3 Code (Codex 30-day: 204 vs 233). There is no cost estimation or persistent ledger cache, so the first 90-day scan of ~1.3 GB of logs takes several seconds. The browser has no freehand drawing annotations, no file:// pages, no download handling, no named profiles (non-private tabs share WebKit's default website data store), no tab reordering or drag-out, and is available only in project chats. Open Web Inspector depends on WebKit SPI. Device mode emulates viewport size only. Open file tabs whose path is missing from the current checkout show “File not found” rather than closing automatically.
5. **Refresh:** manual, app activation and turn-completion refresh are present; filesystem watching is not. A captured attachment intentionally remains a snapshot after edits.
6. **Persistence:** whole-archive JSON with debounced atomic saves; sent screenshots are embedded as base64 PNG data and increase archive size. Separate asset storage is future work. Drafts, approvals, running processes and terminal scrollback do not survive quit. No migrations beyond version rejection, database paging, transcript pruning or multi-process writer protection.
7. **Terminal and keyboard:** test IME, VoiceOver, international layouts, custom Ghostty bindings, long-running sessions and large scrollback. Reserved app shortcuts take precedence over conflicting Ghostty bindings. Shortcut remapping is not yet exposed. Transcript find navigates matching messages, not individual occurrences; search scans the loaded archive without an index. Configuration reuse currently checks `~/.config/ghostty/config`; other Ghostty config locations are not discovered. Missing named Ghostty theme resources can cause the wrapper to fall back to defaults (observed for TokyoNight Moon in the isolated bundle); Catppuccin overrides do not depend on external theme files. No specialized herdr integration; run herdr in an ordinary shell tab.
8. **Packaging:** development bundle only, locally source-built official Ghostty behind Octo’s owned host, no distribution signing identity/notarization/updater/distribution license. The [implementation record](GHOSTTY.md) and [interactive work plan](ghostty-integration-plan.html) track the internal API constraint, build provenance, patch disposition and remaining parity/platform checks. Intel, macOS 14, full IME/VoiceOver, continuous redraw/trackpad profiling, hosted CI and a second-machine clean build remain unverified. App sandbox is off because local tools need filesystem/process access; Codex tool sandbox policy is a separate CLI boundary.
9. **Security review:** the pre-publication audit found no credential matches in the candidate source upload. Transcript permissions, editor socket isolation, process resource bounds, file-preview containment and CI permissions have been hardened. See [the audit and its limits](SECURITY_AUDIT.md). Common credential files, workspace exports, and logs are now ignored; personal checkout details were removed from this document.
