# Architecture

## Composition and dependencies

```text
OctoApp (SwiftUI, AppStore, ReviewModel)
  ├── OctoAgents ── OctoCore
  ├── OctoGit ───── OctoCore
  ├── OctoReview ── OctoCore
  └── OctoTerminal ─ OctoCore + OctoGhostty → locally built GhosttyKit
```

AppStore composes services and owns the persisted project/thread graph. Views communicate through intent methods; adapters emit provider-neutral AgentEvents. Git operations live on GitService's actor. ReviewModel rejects asynchronous results from a superseded project or file selection.

## Chats without a project

A built-in `WorkspaceProject.isChatCollection` container reuses the existing thread graph, provider event routing, persistence, search, Recent, unread state and thread actions. It is rendered as the top-level **Chats** section, excluded from `orderedProjects`, project search and repository actions, and cannot be renamed, pinned as a project or removed. The flag decodes as false for legacy projects, including repositories named Chats. Startup adds the container once without changing a valid existing selection; a fresh workspace selects a reusable draft in Chats. A protected/unreadable archive is never seeded or overwritten.

`WorkspaceStore.prepareChatDirectory` creates private, persistent `ChatWorkspaces/<thread UUID>` directories beside the archive using descriptor-relative no-follow opens. Each chat has a distinct CLI working directory, with no Git initialization or user folder picker. Selection/send revalidate the directory before use; model discovery and provider settings use the same normal adapter paths and permission policies. The collection itself has no repository root. Project-only review, file, terminal and Git actions are absent or disabled in Chats; existing project terminal surfaces stay mounted across navigation. Chat deletion preserves generated files. Moving chats into projects, file management for standalone chats and directory garbage collection are future work.

## Agent sessions

Each active chat has its own harness instance. HarnessID and HarnessRegistry describe locally available providers; AgentHarness exposes send, steer, interrupt, shutdown, and events. Local thread IDs remain stable independently of remote session IDs. Switching projects does not reroute running events: callbacks capture the owning thread ID.

CodexExecutable in OctoAgents resolves a custom absolute executable path first, otherwise a supported desktop-app bundle path, then PATH. A missing explicit override is an error rather than an implicit switch. AppStore persists the override in app preferences, passes the resolved binary to both model discovery and harness creation, closes idle Codex connections when it changes, and rejects changes during active Codex turns. A configuration identity invalidates model caches and ignores discovery responses from a superseded installation. Settings reports the path and `--version` output.

Codex runs a long-lived `codex app-server` over newline JSON. The client initializes, starts/resumes a thread in its checkout, then starts turns. By default it requests `workspace-write`, `on-request` approval policy, and the user approval reviewer. Provider-neutral `AgentPermissionMode` persists in optional `AgentSettings.permissionMode`; the adapter maps Read only to read-only/never, Ask for approval to workspace-write/on-request/user, Approve for me to workspace-write/on-request/auto_review, and Full access to danger-full-access/never. The chosen sandbox, approval policy, and reviewer are passed at start/resume and again on every turn, so changing a resumed thread cannot inherit a previous broader policy. Auto-review is gated to CLI 0.158.0 or newer and version-probed again by the harness before use. Unsupported saved choices block sending without consuming the draft; Selecting Full access requires a native confirmation explaining that it also becomes the new-thread default and settings are locked during a running turn. Command and file-change approvals are presented as individual decisions. Unsupported permission expansion and unsupported MCP schemas are declined with visible notices; unknown server requests return an explicit protocol error. Supported MCP forms and experimental tool questions use the neutral interaction bridge described below. The installed CLI's own policies remain authoritative.

Claude Code uses the bidirectional Claude Agent SDK NDJSON control protocol directly from Swift, without bundling a Python/Node SDK. `ClaudeConnection` initializes and correlates bounded control requests; `ClaudeHarness` starts a fresh CLI process per turn and resumes the recorded remote session explicitly. Arguments use `-p --input-format stream-json --output-format stream-json --verbose --include-partial-messages --permission-prompt-tool stdio --permission-mode auto` by default, or `manual` for an explicit Manual choice. The existing neutral `autoReview` intent maps to Claude Auto and is labeled per provider through `AgentPermissionOption.title`. Initialize’s `current_permission_mode` must confirm Auto before any user input is sent; mismatched modes fail visibly. Missing confirmation is allowed only for Manual compatibility with older CLIs. Model discovery always uses Manual so Auto availability cannot block the catalog. A changed `system/init.permissionMode` is reported visibly. Each new/resumed turn applies its selected model/effort and permissions again. Result delivery closes stdin gracefully with a two-second process-group cleanup fallback; Stop/shutdown invalidate requests and terminate the owned group. Exit without a result is failure. Generation checks prevent startup cancellation and late events from affecting a subsequent turn.

The installed CLI's initialize response supplies Claude model IDs and advertised effort levels; no default effort is invented. Codex discovers its catalog through paginated `model/list` on a read-only app-server connection. HarnessRegistry owns both discovery paths; AppStore caches by provider and checkout, and common model/reasoning/image controls consume capabilities instead of provider switches. Optional provider-neutral AgentSettings persist per thread. Missing saved models/unsupported efforts are rejected, never silently substituted. Claude images use base64 PNG content blocks; text and thinking streaming deduplicate against completed message blocks, with child-agent text excluded from the parent answer.

Claude `can_use_tool` requests become the same operation approval cards as Codex, with exact original input returned on Allow Once and no permission-rule updates. Provider cancellation, completion, Stop, disconnect and shutdown invalidate local IDs; old closures cannot answer a later turn. Bounded single-choice `AskUserQuestion` requests use the common native interaction card, exact question/option strings, explicit submission and optional free text. Multi-select/unsupported formats are declined visibly. Configured CLI allow/deny rules and managed policies remain authoritative. Manual maps to `manual` and Auto maps to `auto`, with Auto as the unset default and explicit saved choices preserved. Claude’s own classifier, permission rules, model restrictions and managed policies decide which operations can run; its OS sandbox remains CLI-configured. Plan mode is not advertised as read-only, and bypass mode is not mapped. Claude owns its plugins, hooks, MCP servers and credentials; Octo adds no separate MCP client or configuration writes; Settings opens the installed CLI’s own sign-in flow as described below. Account/context usage, compaction lifecycle, active steering, generic forms/app-access scopes and automatic Claude titles remain unsupported. See ADDING_A_HARNESS.md.

JSONLineProcess owns bounded framing and stderr capture. OctoCore ManagedSubprocess launches each CLI in its own POSIX process group with nonblocking pipes, bounded outbound queues, and backpressure to MainActor protocol handling. Stop signals the group, escalates from TERM to KILL after 300 ms, drains briefly and reaps the child. Finite commands additionally have a 30-second deadline and an 8 MB combined output limit. Deliberately detached descendants are outside this lifecycle boundary; it is not a sandbox. Complete, fragmented and EOF protocol frames share the 8 MB inbound limit. Unrelated inherited file descriptors are closed at spawn. RPCConnection matches request IDs and propagates disconnects/timeouts. This transport is internal to OctoAgents; protocol fixtures test it without a paid model request.

## Provider command discovery and Claude sign-in

`AgentCommand` in OctoAgents describes entries advertised by the installed provider. Claude reads initialize’s `commands` array on a bounded Manual-mode connection without sending user input. Codex reads `skills/list` for the exact checkout, retaining enabled skills and their absolute provider paths. AppStore caches catalogs by provider/checkout and rejects cancelled or superseded installation/configuration results. The small draft subtree filters the leading slash token and renders the native SwiftUI picker; its NSTextView consumes unmodified arrows, Return, Tab and Escape while the picker is active. Selection inserts text into the owning draft, never submits it, and leaves IME/modified-key behavior intact. The picker closes once arguments start. No skill-file contents, credentials or catalogs enter the saved archive.

On explicit Codex send/steer, a leading `/name` matching an enabled provider skill is revalidated against `skills/list`, then encoded as `$name` text plus the exact native `skill` name/path input. Arguments and captured code context remain intact. Existing sandbox/approval settings still apply; cancellation checks prevent a discovery result from starting a stopped turn or steering a different turn. Unknown slash prefixes remain ordinary text. Claude receives its slash invocation unchanged through its SDK stream. Provider settings, scope and plugins decide which skills are available; there is no cross-provider skill installation or interactive CLI command emulation.

`ClaudeCLI` reads only `auth status --json`, retaining the reported Boolean and method, with signed-out exit code 1 distinguished from unsupported status/errors. Settings separately displays executable presence and authentication. An explicit **Open CLI sign-in** creates a `CLISetupSession` in OctoTerminal for the discovered executable and `auth login` argument array, through the existing shell-quoted terminal launch boundary. Its dedicated Ghostty surface uses Anthropic’s own interactive/browser flow, retains all CLI authentication choices, and closes its owned process on dismissal. It is separate from project terminals and available in Chats. Stop Claude turns before opening it. Closure refreshes status and invalidates Claude catalogs without changing drafts, settings or other providers. The CLI owns credentials and configuration; Octo implements no OAuth endpoint/token storage. Real sign-in completion remains user-operated. See CLI_MCP.md for upstream policy and protocol evidence.

## Queued messages and steering

AppStore holds a bounded FIFO per local thread (20 messages), with immutable text/image/code snapshots and the provider/checkout captured on explicit submission. Queues are session-local, independent of the next draft, and remain visible above the composer. A successful turn drains one entry after returning from the provider callback; Stop, provider interruption, failure and steering errors pause delivery. Manual Send queued resumes a paused queue. Delivery revalidates the provider/checkout and uses the thread's current model/permission settings, including any narrowing since submission. Navigation never changes ownership. Shutdown prevents delayed queue tasks from starting work.

Codex's `turn/steer` carries the current remote thread and `expectedTurnId`, the same text/image input encoding, and no setting or permission overrides. A pending steer stays in the queue and blocks automatic draining until its acknowledgment. Accepted input is inserted at the captured transcript boundary with optional `ChatMessage.isSteering` metadata; it remains part of the initiating `ChatTurn` and does not replace its work clock. Rejected or uncertain delivery remains visible for explicit retry/removal, without automatic retransmission. Questions and approvals are never silently resolved by steering. Claude supports queued subsequent turns only. The native Return handler synchronously reconciles the accepted draft before another key event can append to the previous message.

Codex recognizes activity from the installed `cua_repl` runtime and sends its bundled `turn_ended` Stop/Interrupt hook via app-server `mcpServer/tool/call` when a turn ends. Cleanup uses the original thread/turn IDs, is bounded to five seconds, and settles before delivering the completion event or starting queued work. A confirmed provider cleanup item avoids a duplicate call. The method is conservatively gated to CLI 0.160+; unsupported/rejected cleanup emits a visible notice. Shutdown attempts bounded cleanup before closing its owned transport; abrupt app exit/disconnection cannot guarantee remote cleanup. Octo also clears orphaned running tool rows on every local terminal outcome and ignores late tool starts. This is a narrowly scoped CLI-owned cleanup bridge, not a separate MCP client or desktop overlay implementation.

## Automatic chat titles

OctoAgents owns optional `ThreadTitleConfiguration` and provider title generation. AppStore immediately applies the original first-message fallback on explicit first send, then requests a bounded title separately from the chat harness. Codex configures GPT-6 Luna with low reasoning; Claude configures the CLI's `haiku` alias in print mode with no tools, MCP servers, slash commands, settings sources or saved session, reading `structured_output`. Only bounded typed text is supplied, with no selections, screenshots or prior messages. Generation uses a finite, read-only, ephemeral CLI process outside the checkout, with user configuration/integrations excluded and tools disabled; standard CLI auth and managed policy remain authoritative. Unsupported custom configurations retain the fallback. AppStore injects the generator in tests, tracks cancellable requests by local chat ID, rejects superseded results, and persists manual-title intent so asynchronous work never overwrites a user rename. Auxiliary generation never changes chat model settings, remote session identity, messages or running state. Generated output is bounded to six words / 60 characters; manual and legacy names remain intact. A nonactivating native hover panel displays the complete name, project and last-content-activity age without affecting recent-navigation order or composer focus. The panel uses AppKit labels and equatable display metadata, not a nested NSHostingView. A persistent in-visible-rect tracking area defers/coalesces hover publications outside native layout. Title motion is a one-shot Core Animation transform on an owned CATextLayer containing the complete attributed title, clipped by its native viewport; translating an AppKit-managed text-field backing layer could leave the row blank. The final offset retains the last word, with no per-frame SwiftUI state or geometry updates; dismissal, Reduce Motion and deactivation stop it. Relative age is refreshed when the card opens or its metadata changes.

## Context and token usage

The composer renders a native context ring and detail popover, separate from account quota controls. Provider-neutral `ConversationUsage` snapshots contain the latest model response and cumulative session token breakdowns; optional fields on `WorkspaceThread` preserve the latest report and compaction outcome across relaunch without changing older archives. Snapshots replace counts, never accumulate event notifications. Cache reads/writes are input subsets and reasoning is an output subset; missing values remain unavailable. The last response total divided by the reported model window is a context estimate, not a countdown to compaction or a count of unsent draft text.

Codex maps app-server v2 `thread/tokenUsage/updated` and `contextCompaction` item lifecycle events in OctoAgents. Exact thread/turn identities reject unrelated or stale updates; final accounting for the most recently completed turn can still arrive after `turn/completed`. Compaction item identities deduplicate lifecycle events. Stop, failure, disconnect, shutdown and relaunch cannot leave an active compaction indicator behind. Only provider-confirmed completion is labeled complete. Claude's current print adapter advertises neither usage nor compaction status. No model requests, polling, tokenization, compaction triggers or threshold changes are added by the meter.

## Review and captured context

GitService reads NUL-delimited porcelain status and unified diffs for the selected scope. It never stages, resets or commits files. ReviewSnapshot includes checkout, file, HEAD revision, scope and a content-derived identity. Working diffs compare the index to disk; staged diffs compare HEAD to the index. The snapshot hash captures rendered lines, not a Git object or a promise that the file remains current.

NativeDiffView wraps one AppKit NSTextView using TextKit 2 for stacked review; SideBySideDiffView wraps two for split review. Native selection, scrolling, clipboard and contextual actions are retained. ReviewDocument maps UTF-16 ranges to the underlying source text, excluding headers and gutters. CodeAttachment carries captured text plus old/new ranges. Attaching it populates a draft; sending is explicit. Refreshing replaces the live selection but previously attached captures remain immutable and tell the agent to verify current files.

Both review layouts use lightweight highlighting. ReviewDocument projects each contiguous change block into paired Before/After rows, retaining the original snapshot and source line metadata. Headers and context bound the pairing; unequal blocks use display-only padding with no source segment. Missing-newline notes stay with their version. Side-by-side panes use fixed-height unwrapped paragraphs and synchronized vertical scrolling, with independent horizontal scrolling. Only the active pane publishes selection, asynchronously; snapshot replacement, layout switching and teardown invalidate stale selections. The layout choice is window-local and retains stacked as the default. Richer syntax parsing can be added within OctoReview without replacing app state or harnesses. The native SwiftUI OutlineGroup file tree is built from Git-tracked and non-ignored untracked paths; full-file editing uses a distinct file scope. Both full-file and untracked previews walk checkout-relative directory descriptors with no-follow opens, reject symlink path components and non-regular files, and bound reads to 2 MB.

Manual file actions use `CheckoutFileService` in OctoCore, an actor that performs finite descriptor-relative filesystem work without shell commands or Git index mutations. New files use exclusive creation in an existing directory. Editor sessions and delete dialogs capture the project, checkout, relative path and disk identity when opened; stale-checkout results are ignored. Saves compare the captured identity and exact UTF-8 bytes, write a temporary sibling, preserve ordinary permission bits, then replace atomically after another conflict check. Deletions check the captured identity and unlink only a single regular file after explicit confirmation. Symlinks, hard links, path traversal, Git metadata and non-regular entries are rejected. These checks detect observed external changes; they are not a filesystem transaction locking out independently writing tools.

`NativeFileEditor` edits exact source inline in the Files panel using AppKit/TextKit 2. Line numbers and the hover attachment action are drawn separately from the editable string. `SourceDocument` maps UTF-16 selections to the current buffer and hashes exact source bytes, so unsaved captures carry their own checkout, snapshot and line metadata. Lightweight syntax coloring changes only text attributes; normal typing, IME composition, undo, selection and clipboard use the native text system, with smart substitutions disabled.

AppStore owns `FileEditorWorkspace`, keyed by checkout and path. Sessions retain drafts across project/file navigation; each window retains its native file views for cursor, scrolling and undo. A 500 ms debounce autosaves; Save/⌘S flushes immediately. Saves retain the baseline returned from the write, and typing during a save schedules the next version. Successful saves refresh file/change lists without replacing the editor. Dirty buffers survive refresh and external deletion; clean buffers reload from disk on selection/refresh. A conflict pauses autosave and exposes the retained draft plus explicit Reload with discard confirmation. Delete dialogs pause that file's autosave until cancellation or successful removal. Quit protects outstanding drafts and waits for active file writes. New File uses a path dialog then opens the same inline editor. File editing supports UTF-8 text up to 2 MB; binary/large regular files can be deleted but are edited externally. Folder creation/deletion, draft restoration after relaunch, filesystem watching and bounded editor-cache eviction are not implemented. Deleted tracked paths leave Files (unless retaining an unsaved draft) and remain in Changes.

The native text view tracks source-line hover and shows a gutter + button with a subtle line highlight. TextKit resolves the line geometry; ReviewDocument resolves its UTF-16 source range with a binary search over display segments. The action captures the hovered line, or the current selection when it intersects that line's source text. Headers and empty space below the document have no action; blank source lines are attachable. Snapshot replacement and scrolling clear the hover target so an old range cannot remain actionable.

## Image attachments

The composer uses a plain NSTextView whose paste handler recognizes PNG/TIFF clipboard images, plus a native multi-select image picker opened by its + button. File reads and image conversion run off the main actor; completion revalidates the owning chat, provider and remaining capacity. Sending is disabled during pending imports, and selection never sends automatically. ImageIO checks dimensions before decoding and applies camera orientation; animated images use their first frame. OctoApp converts them to bounded PNG snapshots and holds them per thread as draft ImageAttachments; paste never sends a turn. Draft removal and thread deletion release the captures. Sent messages persist PNG bytes in the local JSON archive, with backward-compatible decoding for older image-free messages. This increases archive size; separate asset storage remains future work. Up to four images per message are accepted, each up to 5 MB PNG/32 megapixels (source representation capped at 30 MB).

AgentHarness accepts provider-neutral image attachments alongside text. Codex maps them to `image` inputs with PNG data URLs; no temporary filesystem path is required. Claude maps them to base64 PNG image content blocks on its SDK input stream. Catalog inputModalities is respected when available (older catalogs default to image-capable, per the app-server contract). Image-only turns are supported. Ordinary text paste, native undo, multiline input and explicit Return sending (Shift–Return adds a new line; ⌘Return remains available) remain available.

## Workspace layout

Sidebar, review and terminal visibility changes take effect immediately without animation, including the compact sidebar overlay and its backdrop. Content adopts its destination width directly. Views remain mounted with clipped offscreen positions and immediate input/focus routing; terminal surface ownership is unchanged. Split containers explicitly size their clip to the complete available width: offset children do not expand a ZStack’s measured bounds. Resize drags remain immediate. Command-hold hint badges separate shortcut characters with spaces.

Assistant response presentation uses a small lossless `MarkdownDocument` parser in OctoCore and SwiftUI block views in OctoApp. Foundation `AttributedString(markdown:)` interprets inline content. Parsing/inline interpretation run in a cancelable background task per response; the last parsed snapshot remains visible until the next complete parsed snapshot replaces it. New fragments never appear in a temporary separate paragraph. Unchanged block text reuses cached inline interpretation; obsolete tails are dropped from the cache. Message text is never rewritten: persistence, search and original-response Copy use the provider's string, while fenced-code Copy uses the exact body. Tool/reasoning output remains literal. This is a bounded feature subset rather than a full Markdown engine; no webview or package is involved.

Draft text lives in a separate observable `DraftStore`, consumed only by the editor subtree. AppStore's draft accessor publishes app-wide changes only when text send eligibility changes, keeping ordinary keystrokes from invalidating the transcript and terminal workspace. NSTextView remains authoritative during editing and marked-text composition; unchanged text and theme attributes are not reassigned on SwiftUI updates. The fixed-height native scroll viewport handles long drafts without elastic overscroll. Return/keypad Enter sends only inside the composer, Shift–Return inserts a newline, marked-text composition keeps Return with the input method, and held Return does not repeatedly send. The existing ⌘Return command remains available outside terminals.

Project and thread pin preferences and project disclosure state are stored in the workspace archive; missing preference fields in older archives default to false. Stable ordering puts pinned items first without changing their project ownership. Thread rows expose a separate trailing pin button on hover or keyboard focus, keep pinned buttons visible, and show a pulsing status while their thread is running. Pinning does not select the thread. AppStore coordinates removal with harness lifecycle and refuses to remove active work.

Chats is the first sidebar section, followed by Projects and Recent. Full-row section headers toggle independent optional archive preferences; legacy archives start expanded. Collapsed headers retain unread counts, and project search/add stay available. The traffic-light row (with the hide-sidebar button) and search field share one floating top bar, so the top of the card has a single backdrop, and the Settings/Account Usage footer floats at the bottom; both are safe-area bars over the navigation scroll view, so the list scrolls beneath their glass and is inset by their height at rest. When any thread is pinned, a three-column avatar strip of pinned threads (Chats first, then projects in sidebar order) precedes the sections; pinned threads also remain in their project lists.

Recent lists up to eight nonempty conversations across projects, ordered by persisted last visit/activity time with legacy message-time fallback and stable ID ties. Successful turn completion records an optional unread timestamp; duplicate completion, stop, failure and shutdown cannot create another success marker. Only the selected chat in a key, active window, visible and following latest output, acknowledges it. Terminal, compact review/sidebar overlays and search suspend acknowledgement. Project counts remain visible when collapsed. Recent rows route through the same thread selection and pin intents as project rows.

The sidebar searches in place while shown: `ThreadSearch` (OctoCore) matches every query word against titles, project names and user/assistant messages, the same rule as the ⌘K palette, which remains the search while the sidebar is hidden. The sidebar uses Messages-style conversation rows: an unread dot, a provider-mark avatar (where projects mix, the subtitle leads with the project name), the title with a trailing Messages-style timestamp, and a one-line preview. `SidebarPreviewCache` reduces the newest reply (or unanswered user message) through `ThreadPreview` once per message and skips running threads, which show typing dots, so streamed text never changes the sidebar presentation. Selection is a solid accent fill with inset hairlines hidden beside the selected row; the pin replaces the timestamp while hovered or focused. Terminal follows a project’s threads as a row with its open tab count. `SidebarThreadLimit` lists the first five ordered threads per project or Chats, plus any selected or running thread beyond them, in order; Show more raises a session-local per-project limit (held by `AppStore`) by ten and Show less resets it. Previous/Next Thread cycles only the threads the sidebar lists, so threads behind Show more are skipped. These navigation views do not own or remount terminal surfaces.

MCP integration is CLI-owned: each harness retains its server configuration, credentials, connections, tool execution and permission policy. Octo renders `ToolActivity` updates and native `AgentInteraction` forms and sends typed responses through `AgentHarness.respond`. Capabilities are declared individually in `HarnessCapabilities`; inventory is absent and never a prerequisite. Codex validates a bounded subset of form schemas, preserves exact app-access choices and scopes, and invalidates requests on provider resolution, turn completion, interruption, disconnect and shutdown. Fresh local UUIDs bind UI to a connection and turn generation; wire IDs never serve as reusable UI identity. Tool activity is deduplicated by connection/turn/item and stored as optional message metadata. Pending forms and answers are not persisted. SwiftUI has no Codex wire-format switches.

The Computer Use adapter also recognizes the installed extension's metadata-only duration advertisement on empty app-access forms. It adds a required neutral choice field for the UI, strips that synthetic field from outgoing content, and maps explicitly advertised session/always choices to `_meta.persist`. Nonempty forms retain their original constraints. Consent is never cached or automatically replayed by Octo; provider policies and lifetime remain authoritative. See CLI_MCP.md for the exact versioned metadata shape.

The selected Codex executable inherits Octo's environment and checkout, including configuration-home selection; the CLI alone loads configuration, authentication and trusted-project overrides. Version probing gates experimental question/extended-form opt-ins to 0.158+. Runtime validation still rejects unknown shapes. Claude's print-mode behavior is unchanged and its interaction capabilities remain false. See [CLI MCP support](CLI_MCP.md) for supported fields, exact scope mapping, lifecycle, setup boundaries, protocol references and verification limits.

The composer has one agent menu whose first level lists providers; each provider's submenu lists its models (catalogs for other installed providers are preloaded per checkout with the same initialize-only discovery), and the current provider's also holds Reasoning and Refresh models. Choosing another provider's model on a thread with history starts a new thread for that provider, labelled in the submenu, with a permission menu to its right (icon-only in narrow panes) driven by `HarnessDescriptor.permissionOptions`. Claude currently exposes CLI defaults only. Reasoning summaries, provider commentary, and tool activity within a user-initiated turn share a collapsed work-summary disclosure; answers, errors, user messages and approval cards remain visible. Search expands matching disclosures. Expansion is session-local; raw messages remain persisted and searchable. A native disclosure style makes the complete work-summary header (label, chevron and trailing whitespace) one accessible button; search still expands matching details. Every message hides its day/time, and every response its Copy button, until hover. The footer keeps its layout space and accessibility availability while invisible; the hidden Copy button does not take clicks, and hover state is local to each message. The active turn shows a live, shimmering Working duration through waiting, approval, and answer streaming. While a turn runs, a fixed-size Stop icon button sits beside Send; the agent controls take the row's free space first, so a compressible text button could shrink out of view. Activity pulses respect Reduce Motion. Legacy assistant messages without provider phase metadata remain visible. The chat column, including conversation and composer, has an 840 pt maximum width centered in the available space.

New Thread reuses an idle, unstarted thread in the target project before creating one. Draft text and attachments remain intact, as do the choices on a populated draft. Empty drafts and newly created threads inherit the last explicitly selected provider and its remembered model, effort, and permissions. Optional archive fields store those defaults across launches, with old archives seeded from their selected thread. Existing duplicate drafts are preserved.

The navigation sidebar has a Projects header with an add-project button; each project retains its new-thread action. A geometry-based SwiftUI shell bounds the sidebar to 240–320 pt and permits a 480 × 600 pt window. Below 800 pt, the same mounted sidebar becomes an overlay with independent open state; navigation dismisses it, while returning to a wide window restores the user's wide-sidebar preference. The overlay hides underlying accessibility and input targets and pauses terminal surface rendering without ending its process. Sidebar, chat/review and file/preview dividers use native AppKit hit targets that own cursor updates, hover tracking and mouse drags together. Hidden dividers disable hit testing/tracking. Drag translations use window coordinates so moving the divider cannot shift its gesture origin. Panel visibility interpolates actual width proposals and position together through an animatable layout modifier; descendants remain mounted, direct drags are immediate, and Reduce Motion disables the animation. Chat/review and file/preview columns use a SwiftUI geometry-based divider that clamps widths during every resize; nesting native split views retained oversized children. Below 737 pt of main content width, review occupies the full main area instead of compressing chat. Both panes remain mounted with their split fraction intact. The right review panel can be hidden with its header button or ⌥⌘B; ⌘1 and code attachment return to the composer in compact mode. Review starts hidden; visibility lasts for the app session. Files and Changes keep their list containers mounted and remember their selections separately; the file tree column can be hidden while a file tab or the empty tree is shown. Browser switching reads only the requested snapshot, retaining the existing native preview until the replacement arrives; selection actions are disabled during that handoff.

## Keyboard and appearance

WorkspaceView builds a context-sensitive command catalog shared by the command palette, Workspace menu, and a window-scoped NSEvent monitor. The same catalog supplies noninteractive shortcut badges on available controls after Command is held for 650 ms. A cancellable hold controller suppresses hints after a key press until Command is released, invalidates stale callbacks, and rechecks window/modifier eligibility at reveal time. A local flags-change monitor passes modifier events through unchanged and clears badges on key-window loss, sheet presentation, and modal contexts. The monitor runs before Ghostty handles key equivalents, recognizes only exact modifier combinations, and yields to Settings, attached sheets, and modal windows. Send/stop/attachment actions are excluded from terminal key routing. The shared palette supports project name/path search (⇧⌘K), chat-content search (also opened by the sidebar’s capsule search field, or the titlebar’s Search all chats button while the sidebar is hidden) and flat file search. Project results use sidebar ordering; selection resolves the current archive by ID, expands the project, and requests composer focus without remounting terminals. Native NSSearchField delegates handle arrow/Return/Escape navigation and thread-find focus. Palette rows and scroll targets use stable entry IDs so filtering cannot reuse another result’s label. Selected actions run from the sheet dismissal callback before requesting destination focus, without a fixed animation timer. The find field stays mounted; workspace transitions immediately transfer or clear native first-responder focus so subsequent keystrokes cannot reach a hidden terminal. Composer and preview requests also use explicit counters without remounting the terminal. Sidebar dialogs and terminal-close confirmation are shared by mouse and keyboard actions.

AppTheme in OctoCore stores a portable identifier, Catppuccin/Dracula Classic palettes, and syntax color roles. Selection color/opacity are explicit per palette so Dracula uses its exact opaque selection token while Catppuccin retains its translucent overlay. AppStore persists the choice in UserDefaults. OctoApp applies SwiftUI appearance and native composer colors; OctoReview recolors attributed text without replacing a snapshot or discarding selection. OctoTerminal uses OctoGhostty's setColors API to update live Ghostty configurations in place. System removes the color overlay; user configuration remains the base where supported. No Neovim configuration files are edited. See KEYBOARD.md for the shortcut contract and references.

## Terminal ownership

TerminalWorkspace owns all tabs for the life of the app; TerminalTab owns an OctoGhostty session. The session retains its native view and C surface across detach/reattach; only explicit close/app shutdown frees it. The process-wide runtime queues Ghostty wakeups onto MainActor regardless of visibility. Pending clipboard operations are denied before teardown and queued callbacks are invalidated. TerminalSurfaces keeps inactive tabs mounted and disables their rendering/focus. Closing a tab is an explicit action because it ends its process.

New shells use the selected project's root. Open in LazyVim targets the thread's checkout, reusing one Neovim tab for that project/checkout via a local server socket inside a uniquely allocated, owner-only directory. The directory has a short path for Unix socket limits and is released with editor exit/tab lifetime. Remote-open uses argument arrays and a JSON-encoded Lua argument. A new editor starts `nvim --listen` with the selected file and line inside an explicitly quoted shell launch. After Neovim exits (including an error exit), the launcher writes a completion marker in the private socket directory and execs the user’s `$SHELL` as an interactive login shell, falling back to `/bin/zsh` if unavailable. A tab-owned, cancellable MainActor task checks that marker every 250 ms while the editor is active; startup without a socket is not mistaken for exit. Completion releases the editor socket directory and changes the observed tab title to Terminal without replacing its Ghostty surface. Subsequent editor opens create a fresh editor tab, preserving the returned shell; active editors still reuse their socket. No keystroke injection into an unknown foreground shell is used. Existing `~/.config/ghostty/config` and Neovim configuration are reused where supported by the owned host. See [Ghostty integration](GHOSTTY.md) for the pinned source build, clipboard policy, unsupported actions and platform/input validation limits.

## Persistence and future growth

WorkspaceStore writes schema-versioned JSON atomically using private 0600 temporary files. The standard storage directory is 0700, and old archives are tightened on load. Archives and standard storage are excluded from macOS backups. Storage inside a Git checkout, symlinked archive files, multiply-linked files and unsafe custom parent directories are rejected. Conversations are local to each Mac and are never part of source setup or Git synchronization. Unsupported or corrupt data blocks writes for that app launch rather than overwriting the file. Save requests are debounced. Terminal processes and drafts are session-local.

This format is intentionally small and understandable. Before large histories or multiple app writers, introduce a storage protocol, transactional database, migrations, paging and a single-writer strategy. Before external plugins, replace the closed HarnessID registry with stable identifiers and a capability schema. Worktree creation, branch switching, file watching and session recovery belong in explicit services rather than view callbacks.

## Project actions panel

Menus drawn as hover buttons (`hoverMenuStyle`, `ChevronMenu`) open from their whole highlighted box; borderless-button menus take clicks only on their label, so padding or hover feedback around them looked clickable but was not.

While the review panel is hidden in a project chat, `ProjectActionsPanel` floats beside the centered chat column when the margin fits it, otherwise it opens as a titlebar popover. It is an Equatable view fed plain values from `ReviewModel` (branch, local branches, `DiffStat`, change count) so streamed store publications skip it. Git work stays on GitService's actor: `localBranches` (`for-each-ref refs/heads`), `switchBranch` (validated against that list, `switch --no-guess`) and `diffStat` (`diff --numstat HEAD`). Open-in targets are fixed bundle identifiers resolved through Launch Services and opened with `NSWorkspace` (no shell); LazyVim uses `TerminalWorkspace.openDirectoryInEditor`, the same quoted editor-session launch boundary as file opens. Provider marks are SVG path data rendered by `SVGPathData` into cached template or tinted `NSImage`s.

## Account usage

`HarnessRegistry.usage` returns provider-neutral `AgentUsage` buckets and windows. Codex initializes a separate app-server connection and calls `account/rateLimits/read`, without starting threads or model turns. Its adapter prefers the multi-bucket response and falls back to the legacy single bucket, preserves absent percentages/durations/resets as unknown, and converts Unix reset seconds to dates. The Usage popover refreshes on opening or explicit refresh, labels the account-wide scope and last update, and displays actual window durations instead of inventing a monthly allowance. Live `account/rateLimits/updated` notifications merge the affected bucket. In-memory caches are scoped to provider/checkout and invalidated on executable changes; stale responses from a superseded installation are ignored. Claude has no read-only limit query (`get_usage` is explicitly experimental upstream), so `supportsUsageRefresh` is false and limits arrive only as SDK `rate_limit_event` messages for the active session. `ClaudeHarness.decodeRateLimit` maps the public `status`/`rateLimitType`/`utilization` (a fraction; values above 1 clamp remaining at zero)/`resetsAt` fields and, when present, the upstream-internal `unifiedWindows`; missing values stay unknown and a rejection is shown as “Limit reached”. `AgentUsage.merging` replaces windows by id inside a bucket so a single-window event keeps other last-known windows. Claude snapshots are keyed by provider alone because the limit is account-wide. No credentials, usage data, or permission choices are copied into source setup.

## Usage dashboard

`UsageLedger` (OctoAgents) reads the CLIs' own session logs: `$CODEX_HOME` or `~/.codex` `sessions` and `archived_sessions` rollouts, and `$CLAUDE_CONFIG_DIR` or `~/.claude` `projects` transcripts. Lines are prefiltered by byte markers before JSON decoding. Claude usage is counted once per `message.id`+`requestId`, because each content block repeats it. Codex usage is the increase in cumulative `total_token_usage`, which skips repeated events and falls back to `last_token_usage` when a counter restarts, attributed to the latest `turn_context` model. Codex `input_tokens` includes cached input. Records are aggregated per model/session/hour, cached per file by size and modification date, and files modified before the range start are skipped. `UsageSummary` is pure: it fills empty hourly or daily buckets, ranks providers and models, and splits processed tokens into cached input, cache writes, uncached input and output. The SwiftUI `Window` uses Swift Charts. It makes no network requests and does not estimate costs.

## Browser panel

Panel tabs are a per-project `PanelTabs` value (OctoCore) persisted on `WorkspaceProject.panelTabs` (absent in older archives). Every tab closes, including Changes; the selection is `nil` exactly when none is open, and the panel then shows a focusable surface picker with single-letter keys. File tabs hold checkout-relative paths, so they follow the selected thread's checkout; at most one file tab is a replaceable preview; the `.files` tab is the tree with no file open and is replaced by the first file opened. Decoding drops duplicate/unknown tabs, keeps an empty tab list, and falls back to the first tab for a missing selection. Private browser tabs and their addresses are never encoded. `ReviewModel.adopt/show` mirror the selected tab: file tabs reuse `FileEditorWorkspace` sessions, so switching tabs keeps buffers, undo and cursor without keeping every editor mounted; browser tabs leave review state untouched.

`BrowserSession` (OctoApp) owns one `WKWebView` per browser tab, held by AppStore keyed by tab ID and re-parented into its `BrowserPane`. Every open browser tab of the current project stays mounted (opacity toggled), so pages survive tab, panel and project switches; closing a tab stops and discards its page. Restored tabs show their saved address and load only when first shown. Private tabs use `WKWebsiteDataStore.nonPersistent()`; others share WebKit's default store, so Clear Cookies/Clear Cache in a default tab affect every non-private tab. Navigation allows http(s)/about/data/blob. Other schemes leave the app only on an explicit link click; `javascript:` and `file:` are never opened. `createWebViewWith` builds a new session from WebKit's pop-up configuration (same data store, `window.opener` kept) and AppStore adds it as a tab; `webViewDidClose` closes it. Each session installs its own `WKUserContentController`, because a pop-up's configuration carries the opener's controller and its annotation handler. Hard Reload uses `reloadFromOrigin`; zoom sets `pageZoom`; Appearance sets the web view's `NSAppearance`, which drives `prefers-color-scheme`. The device toolbar sizes the web view to a preset and, when it does not fit, shrinks both the frame and `pageZoom` by the same factor so the CSS viewport stays exact; WebKit keeps its macOS engine and user agent, so this is width/height emulation, not touch or mobile UA emulation. Open in Separate Window moves the live web view into an `NSWindow`; closing it returns the page. **Open Web Inspector** calls WebKit's `_inspector`/`show` SPI found at runtime (no public API exists). WebKit ignores `show` unless the page's `developerExtrasEnabled` preference (also SPI, set by KVC only when `_setDeveloperExtrasEnabled:` exists) is on, which also adds Inspect Element to the context menu; when either is absent the item is disabled, and Safari's Develop menu still works because pages are inspectable. The annotation picker is evaluated in the `OctoAnnotate` `WKContentWorld`, and its message handler is registered only for that world, so page scripts cannot call it, read its state or pre-empt it. Clicks pick an element and drags pick a region; Escape cancels. The app ignores the page's reported URL/title in favor of the web view's, bounds every field in `BrowserAnnotation` (OctoCore), and crops a snapshot after screen updates. `AppStore.attachBrowserAnnotation` checks the owning project, adds the screenshot when the provider accepts images and fewer than four are attached, and appends the annotation to the draft. On send, annotations are appended to the prompt as `<browser_annotation>` blocks that label page content as untrusted data and escape embedded closing tags. They persist on the user message (`browserAnnotations`, decoded as empty for older archives).

## Transcript presentation and navigation

Working indicators are native: the live dot is a Core Animation shape layer whose ring expands and fades, a working sidebar row rings its avatar and fades three typing dots in sequence the same way, the compaction symbol is an AppKit image with an opacity pulse, and the Working label is an AppKit label with a brighter copy revealed through an animated gradient mask. The shimmer animates gradient locations, which are relative to the layer, so the per-second timer text can change width without restarting the sweep. The animation never schedules SwiftUI state or graph updates, retains its phase across unchanged updates/theme changes, and stops for Reduce Motion, inactive scenes, hidden native ancestors and detachment. The same applies to the dot and shimmer. This avoids the reproduced whole-window layout runaway caused by repeating SwiftUI symbol effects in the sidebar. The sidebar and review panel are floating glass cards drawn by AppKit's `NSGlassEffectView`, not SwiftUI's `glassEffect`: the SwiftUI effect laid out beside any of these Core Animation indicators re-laid out the hosting view about 10,000 times a second on macOS 26.6. `WindowChrome` makes the titlebar transparent over full-size content and moves the traffic lights into the sidebar card's top row, observing the buttons' frame changes to restore them after AppKit lays out the titlebar again; they stay inside the 32 pt titlebar so they keep their full hit area. It installs no toolbar: on macOS 26 a toolbar's `NSToolbarView` draws a full-width glass band. The window group uses `.windowStyle(.hiddenTitleBar)`: with the default style, SwiftUI restores an opaque titlebar on every colour-scheme change. The workspace ignores the top safe area.

The sidebar observes a coalesced, equatable display snapshot: project/thread identities and ordering metadata, titles, pins, disclosure, unread/working state, selection, hover dates, terminal ownership and sidebar edit requests. Transcript-only archive publications do not invalidate its rows or lazy placement. Native row actions still resolve through AppStore, and theme/shortcut environments update independently.

AppStore coalesces assistant, reasoning and activity text across active chats into one archive publication per 33 ms, with a 64 KiB flush bound. Protocol boundaries, Stop, explicit saves and shutdown flush pending text first; role and tool boundaries are preserved. Transcript follow intent is owned by `TranscriptScrollController`, observing the enclosing native NSScrollView through a noninteractive SwiftUI background probe. Native user-scroll notifications pause following when more than 32 pt from the bottom and resume near the bottom; content/frame changes never pause following. “Scroll to end” explicitly resumes. All turns remain eagerly measured while a chat is open. This prevents lazy history estimates and recreated asynchronous Markdown views from changing document height during scrolling. It trades additional mounted views and initial layout work for stable scrolling; very large histories still need measured-height virtualization. Native document/viewport size changes plus SwiftUI text/height changes request coalesced native clip movement after a 16 ms layout deferral. ScrollViewReader remains for explicit search navigation; it no longer reanchors the transcript for every streaming delta. A local wheel-event monitor pauses follow before native movement and through momentum/180 ms of wheel inactivity, covering legacy wheels and the gap after finger lift. Bounds-origin changes, unchanged probe connections and ordinary gesture completion do not request a jump; an already-visible end leaves native elastic scrolling untouched. Explicit resume and new chat connections can still force a jump. Scrolling handles late Markdown layout and viewport resize, cancels pending movement during live scrolling, and disconnects observers on teardown. Thread changes start at the latest content; find pauses following, and hidden-terminal suspension retains follow intent. Probe configuration is deferred beyond SwiftUI view updates. Native review selection callbacks are deferred and deduplicated by snapshot and range; text replacement suppresses intermediate delegate callbacks so selection cannot synchronously publish SwiftUI state during `updateNSView`.

User messages appear in right-aligned rounded bubbles; assistant responses remain unboxed. Timestamp footers use each message's recorded date, with a full-date tooltip; completed assistant responses use an optional completion timestamp. `TurnWork` is optional metadata on the initiating user message. AppStore records elapsed work using system uptime, finishes it on completion/failure/interruption, and preserves stopped/failed/interrupted labels. A saved unfinished run is shown as Interrupted without inventing an end time. Older archives have no duration and continue to decode unchanged. Work details are grouped per user turn; search expands matching details.

Markdown tables use a native SwiftUI Layout that allocates columns across the available transcript width, measures wrapped cells, and sizes each row to its tallest cell. Thin horizontal separators replace boxed cells; wide tables retain horizontal scrolling. The Usage header control is chart-only with a tooltip and accessibility label.

Assistant links intercept OpenURL: HTTP(S)/mailto retain normal system routing; local destinations go through `MarkdownFileLink`, resolved against the thread checkout. Relative, absolute, file URLs, `:line[:column]`, and `#Lline` references are supported. Out-of-checkout paths and unsupported schemes report an Octo error. Native Files navigation expands ancestors, selects the file, and scrolls/selects a referenced line without attaching or sending it. Existing bounded no-follow GitService reads still enforce file containment. Folder expansion is explicit view state so link navigation can reveal nested files.
