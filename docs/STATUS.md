# Current status

Updated 2026-09-26. This is a working native development foundation, not a complete Codex/T3 replacement.

## Implemented

- Security hardening: owner-only atomic local archives with backup exclusion and legacy permission tightening; archive paths inside checkouts are rejected. Neovim sockets use private short-lived directories. Managed CLI processes use bounded nonblocking I/O, finite-command deadlines, process-group cancellation and escalation; protocol frame limits cover complete and fragmented input. File previews use bounded descriptor-relative reads and reject symlinks/non-regular files.
- New-Mac setup: `make setup` checks prerequisites, enables repository privacy hooks, scans files, and builds Octo. `make doctor` performs checks only. Each Mac starts with an empty, independent local workspace; provider authentication and Neovim configuration remain local. Privacy hooks and CI detect known credentials and renamed Octo archive JSON; push checks inspect history. CI checkout is pinned with read-only token permissions and no persisted credentials.

- Keyboard-first workspace: ⌘B sidebar, ⌘K chat search, ⌘F current-thread find, ⌘N new thread, ⌘P file finder, ⇧⌘P command palette, numbered destinations, terminal tab controls, and keyboard code attachment. Palette and native menus expose context-sensitive actions; existing confirmation and approval boundaries remain. Window-scoped routing keeps reserved app shortcuts working from Ghostty and preserves terminal Control/Option-only/leader keys. See KEYBOARD.md.
- Bottom-left Settings button with Appearance, Keyboard, and Agents tabs. Persisted macOS System / Catppuccin Latte / Catppuccin Mocha choices apply to the shell, composer, native preview, and live terminal colors. Theme updates preserve terminal surfaces and review selections; installed Neovim colors remain independent.

- SwiftUI macOS app, project/thread sidebar, separate chat and code-review areas.
- Custom macOS app icon using the supplied sunglasses-octopus artwork. The original is retained under Resources/Branding; the Xcode asset catalog includes all 16–1024 pixel representations for Debug and Release bundles.
- Locally persisted projects, threads, messages and remote session IDs.
- Sidebar polish: full-width thread hit targets, hover feedback, 14–15 pt primary text, collapsible project folders, pinned projects and threads, and right-click actions for new threads, pinning, renaming, deletion/removal and Finder reveal. Pin/collapse state survives relaunch; older archives load with sensible defaults.
- Removal leaves repository files and CLI history intact. Running threads cannot be deleted; projects with active agents or open terminal tabs must be stopped/closed first. Local conversation deletion requires confirmation.
- Stable Files/Changes layout with independent remembered selections; preview remains mounted while the next snapshot loads. Width-clamped, draggable review/chat columns keep the sidebar and controls usable down to the 1080 pt minimum window width. Terminal tab headers scroll horizontally.
- Projects header with an add-project + button; redundant top-right Add Project/New Thread toolbar buttons removed. Per-project new-thread + and keyboard commands remain. Click the project name or folder icon to expand/collapse its children, with open/closed folder artwork and no disclosure chevron; toggling preserves the active conversation.
- Right review-panel show/hide button and ⌥⌘R shortcut. Chat expands when hidden; review stays mounted with its selection and split width. Visibility is session-local.
- Codex composer model and reasoning menus from the installed CLI's paginated model catalog. Choices persist per thread, apply to new/resumed/subsequent turns, and are locked while a turn runs. Switching models retains compatible effort or adopts the model default. Catalog errors can be retried; missing saved choices remain visible and are rejected before sending when a catalog is available. Older threads retain session defaults until explicitly changed.
- Codex executable selection: automatic discovery prefers the desktop-app bundle over PATH; Settings shows the exact path/version and allows a persisted custom executable. Model discovery and generation use the same selection. Changes invalidate catalogs and idle connections; active Codex turns block installation changes. Missing custom paths fail explicitly.
- Compact composer agent menu with nested Provider, Model, and Reasoning choices. Chat content is centered and capped at 840 pt, including when review is hidden.
- Screenshot paste into the native message editor, removable draft thumbnails, image-only Codex turns, and persisted image previews in sent messages. Paste never sends automatically. PNG/TIFF clipboard images are normalized to PNG; limits are four images, 5 MB PNG/32 megapixels each. Claude image input is explicitly unsupported.
- Provider contract and registry; Codex app-server and Claude Code print/stream adapters.
- Codex streaming, resume, interruption, command/file approval cards and explicit unsupported-request handling.
- Native AppKit/TextKit 2 unified diff with source-aware selection, contextual Ask Agent, and draft attachments.
- Hover feedback on agent settings, terminal/review controls, browser tabs, scope and editor actions, change/file rows, and composer actions. Selected buttons also respond to hover; disabled controls do not advertise an active hover state.
- Native diff and full-file previews show a highlighted source line and gutter + on hover. Click to attach that line, or an intersecting text selection, to the draft with checkout/snapshot and old/new line metadata. Headers and space below the document are excluded; blank and Unicode source lines are supported. Sending remains explicit.
- Staged versus working changes, untracked text previews, binary/large-file notices.
- Native hierarchical file browser for tracked and non-ignored untracked files; full-file preview with the same selection actions.
- Embedded Ghostty with a persistent terminal workspace per project and generic tabs.
- Open in LazyVim using the installed Neovim configuration; reuse a dedicated editor tab per project/checkout using a local socket.
- SwiftPM modules, Xcode app target/shared scheme, build script, Makefile, CI definition, contributor and architecture docs.

## Known limits and next work

1. **Agent hardening:** live harness smoke tests, richer tool output, Claude model/reasoning controls, additional provider settings, token accounting, reconnection, more approval/request types and cancellation races. Resource limits and process-group shutdown are implemented; deliberately detached descendants remain outside that ownership boundary.
2. **Workspace lifecycle:** archive/restore and undo for removed threads/projects, explicit worktree creation/selection, branch operations and multi-window ownership. Current new threads use the project's current checkout; Octo does not isolate them automatically.
3. **Review polish:** side-by-side rendering, character-level changes, proper syntax grammars, search, line-gutter selection, reliable copied-source formatting, and performance benchmarks. Ordinary native Copy includes visible gutter text; Ask Agent strips gutters. File listings exclude ignored files and do not traverse submodule contents. File previews reject symlink components, including links inside the checkout. No stage/commit UI.
4. **Refresh:** manual, app activation and turn-completion refresh are present; filesystem watching is not. A captured attachment intentionally remains a snapshot after edits.
5. **Persistence:** whole-archive JSON with debounced atomic saves; sent screenshots are embedded as base64 PNG data and increase archive size. Separate asset storage is future work. Drafts, approvals, running processes and terminal scrollback do not survive quit. No migrations beyond version rejection, database paging, transcript pruning or multi-process writer protection.
6. **Terminal and keyboard:** test IME, VoiceOver, international layouts, custom Ghostty bindings, long-running sessions and large scrollback. Reserved app shortcuts take precedence over conflicting Ghostty bindings. Shortcut remapping is not yet exposed. Transcript find navigates matching messages, not individual occurrences; search scans the loaded archive without an index. Configuration reuse currently checks `~/.config/ghostty/config`; other Ghostty config locations are not discovered. Missing named Ghostty theme resources can cause the wrapper to fall back to defaults (observed for TokyoNight Moon in the isolated bundle); Catppuccin overrides do not depend on external theme files. No specialized herdr integration; run herdr in an ordinary shell tab.
7. **Packaging:** development bundle only, pinned community Ghostty binary, no distribution signing identity/notarization/updater/distribution license. App sandbox is off because local tools need filesystem/process access; Codex tool sandbox policy is a separate CLI boundary.
8. **Security review:** the pre-publication audit found no credential matches in the candidate source upload. Transcript permissions, editor socket isolation, process resource bounds, file-preview containment and CI permissions have been hardened. See [the audit and its limits](SECURITY_AUDIT.md). Common credential files, workspace exports, and logs are now ignored; personal checkout details were removed from this document.

## Resume here

Open `Octo.xcodeproj`, select the shared Octo scheme, or use `make run`. Run `make test` before changing adapters or selection mapping. Read ARCHITECTURE.md and ADDING_A_HARNESS.md. The repository uses `main`; review the privacy checks before committing or pushing.

`design-prototype.html` is the historical browser concept used during ideation. It contains earlier naming and mock data; source code and this status document describe the implemented app.

## Polish references and development verification

The project/thread hierarchy and restrained controls follow [Codex’s app overview](https://openai.com/index/introducing-the-codex-app/). Menu-based pinning and keeping pinned work above other threads follow [T3 Code’s thread sidebar guide](https://github.com/pingdotgg/t3code/blob/main/docs/user/thread-sidebar.md). Octo keeps its native SwiftUI/AppKit implementation.

Set `OCTO_WORKSPACE_PATH` to a separate JSON archive when launching a development smoke-test instance. It overrides only Octo workspace storage; use a distinct app bundle identifier to run it alongside a personal Octo instance. Never run two writers against the same archive.

## Model-control references

The composer uses model-specific reasoning choices and retains unavailable selected labels, informed by [T3 Code's ProviderModelPicker](https://github.com/pingdotgg/t3code/blob/main/apps/web/src/components/chat/ProviderModelPicker.tsx). Protocol fields are verified against installed Codex CLI **0.151.0**, app-server **v2** generated schemas (`ModelListResponse`, `ModelListParams`, `ThreadStartParams`, `ThreadResumeParams`, and `TurnStartParams`), with [upstream app-server documentation](https://developers.openai.com/codex/app-server). Model lists are discovered at runtime rather than hard-coded. Catalog discovery has been exercised against the installed CLI; generation remains fixture-tested only.

Executable discovery fix: this Mac's Homebrew CLI 0.151.0 returns only GPT-5.6/GPT-5.5 in the visible catalog; the ChatGPT-bundled CLI 0.158.0-alpha.2 also returns GPT-6 Astra, Sol, and Luna. Automatic selection now uses the latter. Desktop-app paths are integration conventions, not a stable embedding contract; custom selection covers other locations. The version probe uses the bounded finite-process runner with its 30-second deadline.

Screenshot input mapping was checked against Codex CLI 0.158.0-alpha.2 app-server v2 `TurnStartParams.UserInput` (`image`/`url`) and `Model.inputModalities`; see [app-server input documentation](https://developers.openai.com/codex/app-server). Protocol delivery is tested with a local fixture, without paid generation.
