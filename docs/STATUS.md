## Implemented

- **Native Git actions, design A “Changes, with actions” (2026-10-21, latest):** the Changes tab now stages, commits, stashes, pushes and opens pull requests while keeping the shell, floating panels, native review and chat layout. A Git row shows the branch, **Push N** (or Publish for an untracked branch), **Create PR** / **PR #n**, a More menu (Stage All, Unstage All, Stash Changes…, Stashes…, Fetch, Discard All Unstaged Changes…) and refresh; beneath it the upstream state (`origin/x · 2 to push · 1 behind`, Not on origin, No remote) and Stashes (n). Files are grouped as **Staged** and **Unstaged**, each with Unstage All / Stage All and a visible + / − on every row; per-scope line counts. The diff header adds Discard (unstaged only) and Stage File / Unstage File, a HEAD → Index / Index → Working tree label beside the layout picker, and **Stage Hunk / Unstage Hunk** buttons on every `@@` row (also in the code's contextual menu; side by side shows them on After). An inline composer commits only staged changes; afterwards a card shows the hash and offers the next explicit step, Push or Create PR. Discard is confirmed, names the files, and keeps staged changes. Named stashes (optionally with untracked files) apply, pop and drop (confirmed) with their staging restored. Pull requests go through the installed `gh` (draft by default, base picker, prefilled title/description); the sheet requires an explicit Push Branch first when commits are unpushed. Push failures show a banner that the commits are saved locally, with a cause-specific hint, Retry and Git's output. Not included: AI-generated commit/PR text (would need a model call), hunk-level discard, force push, pull/rebase, conflict resolution UI, and choosing among several remotes without origin. See ARCHITECTURE.md › Native Git actions. - **Installed app and Octo Dev (2026-10-21, later):** Two copies with separate jobs. `make install` builds Release and installs **Octo** (`dev.octo.app`, chats in `Application Support/Octo`) to `~/Applications` (`OCTO_INSTALL_DIR` overrides). - **Terminal splits (2026-10-21):** each terminal tab holds a tree of Ghostty panes. Ghostty's own bindings drive it, so ⌘D / ⇧⌘D split right/down, ⌘[ / ⌘] and ⌥⌘ arrows move focus, ⌃⌘ arrows resize, ⌃⌘= equalizes and ⇧⌘Return zooms, and the user's custom `new_split`/`goto_split`/`resize_split`/`equalize_splits`/`toggle_split_zoom` bindings work the same way. A new split is a shell in the focused pane's current directory and font size, as `split-inherit-working-directory` and `window-inherit-font-size` pass on, and falls back to the checkout if that directory is gone. `SplitLayout` in OctoCore follows Ghostty's macOS `SplitTree` rules for insertion, removal, spatial and cyclic focus, point-based resize (ratios clamped to 10–90%) and equalize. Panes are positioned by frame rather than nested stacks, so splitting, closing, zooming and dragging move and resize surfaces without remounting them; a zoomed-over pane stays mounted with rendering and input off. Dividers use the app's `ResizeHandle` (Ghostty's `split-divider-color` when set) and can be dragged; unfocused panes are dimmed by `unfocused-split-opacity`/`unfocused-split-fill`. A pane whose shell exits closes and focus moves to the previous pane; a tab's last pane still stays to show its exit. ⌘W closes the focused pane when a tab is split, through Ghostty, which confirms only when a program is running; it still closes the whole tab with confirmation when there is one pane. Split commands are in the palette, the Workspace menu (with Ghostty's default shortcuts as hints; Octo does not route those keys), the tab context menu and the terminal's right-click menu; a zoomed tab shows an icon. Opening a file in an editor tab focuses the editor's pane. 18 tests cover the layout rules, pane lifecycle, focus and a hosted check that the first pane keeps its native view while it is resized. `OCTO_LIVE_TERMINAL_TESTS=1 swift test --filter LiveSplitSmokeTests` drives real surfaces and the user's shell in a window: Ghostty's `new_split` binding and ⇧⌘D key handling, directory inheritance, focus, resize, equalize, zoom and `exit` closing one pane; passed repeated runs. Splits do not survive quit, like tabs. **Not verified natively in the app:** real keypresses (the test process cannot take key focus), divider dragging and cursor, dimming, and the context menus. Shortcut hints assume Ghostty's defaults.

## Known limits and next work

1. **Agent hardening:** real MCP/Computer Use and model smoke tests, additional form/result formats, additional Claude permission/provider settings, Claude subagent token totals, reconnection, more approval/request types and cancellation races. Resource limits and process-group shutdown are implemented; deliberately detached descendants remain outside that ownership boundary.
2. **Workspace lifecycle:** archive/restore and undo for removed threads/projects, explicit worktree creation/selection, branch operations and multi-window ownership. Current new threads use the project's current checkout; Octo does not isolate them automatically.
3. **Review polish:** character-level changes, proper syntax grammars, search, line-gutter selection, reliable copied-source formatting, and performance benchmarks. Ordinary native Copy in Changes includes visible gutter text; Ask Agent strips gutters. Files copies exact source text. File listings exclude ignored files and do not traverse submodule contents. File previews reject symlink components, including links inside the checkout. The manual editor supports UTF-8 files up to 2 MB; mutations reject symlinks, hard links, Git metadata and non-regular files. New-file paths use existing folders; no folder creation/deletion or editor-draft restoration after relaunch. Opened native editors are cached in memory without eviction; large-file performance is not benchmarked. Deletion is permanent, with confirmation. Conflict checks cannot lock out independent writers between the final check and mutation. No stage/commit UI.
4. **Usage and browser:** Claude limits are in-memory and reset on relaunch until another response reports them; API-key/Bedrock/Vertex sessions never report them. `unifiedWindows` is an upstream internal field read only when present. The dashboard reads only local logs on this Mac (other machines and web/desktop app usage are absent); session counts differ slightly from T3 Code (Codex 30-day: 204 vs 233). There is no cost estimation or persistent ledger cache, so the first 90-day scan of ~1.3 GB of logs takes several seconds. The browser has no freehand drawing annotations, no file:// pages, no download handling, no named profiles (non-private tabs share WebKit's default website data store), no tab reordering or drag-out, and is available only in project chats. Open Web Inspector depends on WebKit SPI. Device mode emulates viewport size only. Open file tabs whose path is missing from the current checkout show “File not found” rather than closing automatically.
5. **Refresh:** manual, app activation and turn-completion refresh are present, and the checkout's Git directory is watched, so a branch switch, commit, stage or pull from a terminal or agent refreshes Changes and the branch shown (debounced 0.4 s). Edits to working files alone are not watched. A captured attachment intentionally remains a snapshot after edits.
6. **Persistence:** whole-archive JSON with debounced atomic saves; sent screenshots are embedded as base64 PNG data and increase archive size. Separate asset storage is future work. Drafts, approvals, running processes and terminal scrollback do not survive quit. No migrations beyond version rejection, database paging, transcript pruning or multi-process writer protection.
7. **Terminal and keyboard:** test IME, VoiceOver, international layouts, custom Ghostty bindings, long-running sessions and large scrollback. Reserved app shortcuts take precedence over conflicting Ghostty bindings. Shortcut remapping is not yet exposed. Transcript find navigates matching messages, not individual occurrences; search scans the loaded archive without an index. Configuration reuse currently checks `~/.config/ghostty/config`; other Ghostty config locations are not discovered. Missing named Ghostty theme resources can cause the wrapper to fall back to defaults (observed for TokyoNight Moon in the isolated bundle); Octo's named theme overrides do not depend on external theme files. No specialized herdr integration; run herdr in an ordinary shell tab.
8. **Packaging:** development bundle only, locally source-built official Ghostty behind Octo’s owned host, no distribution signing identity/notarization/updater. Octo's source is MIT-licensed (`LICENSE`); vendored Ghostty keeps its own license and still needs a redistribution review. The [implementation record](GHOSTTY.md) and [interactive work plan](ghostty-integration-plan.html) track the internal API constraint, build provenance, patch disposition and remaining parity/platform checks. Intel, macOS 14, full IME/VoiceOver, continuous redraw/trackpad profiling, hosted CI and a second-machine clean build remain unverified. App sandbox is off because local tools need filesystem/process access; Codex tool sandbox policy is a separate CLI boundary.
9. **Security review:** the pre-publication audit found no credential matches in the candidate source upload. Transcript permissions, editor socket isolation, process resource bounds, file-preview containment and CI permissions have been hardened. See [the audit and its limits](SECURITY_AUDIT.md). Common credential files, workspace exports, and logs are now ignored; personal checkout details were removed from this document.
